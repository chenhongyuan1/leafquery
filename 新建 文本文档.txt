风险计算层的目标
输入：

crop 作物
disease 病虫害
region_code 一级分区
target_date 目标日期
近几天天气 + 未来 7 天天气
phenology_stage 物候期
可选：官方报告风险提示、用户识别观测
输出：

risk_score：0 到 1
risk_level：0/1/2/3
trend_direction：上升/平稳/下降
top_drivers：主要原因
一、整体结构
1. 输入标准化层
先把原始数据统一成一套结构。

建议整理成：

{
  "crop": "冬小麦",
  "disease": "白粉病",
  "region_code": "HHH",
  "target_date": "2026-04-10",
  "phenology_stage": "拔节期",
  "weather_history": {
    "temp_mean_3d": 18.2,
    "humidity_mean_3d": 84,
    "rain_sum_7d": 18.5,
    "consecutive_rain_days": 3
  },
  "weather_forecast": [
    {"date": "2026-04-10", "temp": 19, "humidity": 86, "rain": 4},
    {"date": "2026-04-11", "temp": 20, "humidity": 83, "rain": 2}
  ],
  "report_risk_hint": 2,
  "observation_signal": 0.3
}
二、先验规则层
这是第一层，也是最重要的一层。
它不依赖大量训练数据，直接根据农业知识给一个 prior_risk。

规则层建议拆成 5 个子分数
1. phenology_risk
病虫害是否处于敏感物候期。

例如冬小麦白粉病：

返青期：0.15
拔节期：0.30
抽穗期：0.25
成熟期：0.05
2. humidity_risk
湿度是否达到高风险区间。

例如：

湿度 < 60% -> 0.05
60%-80% -> 0.15
80% -> 0.30

3. rainfall_risk
降雨和连续阴雨是否利于病害。

例如：

近 7 天降雨 < 5mm -> 0.05
5-20mm -> 0.15
20mm -> 0.25

连续降雨天数 >= 3 再加 0.05
4. temperature_risk
温度是否落在病害适宜区间。

例如白粉病：

适宜温度区间 15-22°C -> 0.20
次适宜 -> 0.10
不适宜 -> 0.03
5. report_risk
官方报告或技术方案提示的区域风险。

例如：

未提及 -> 0
偏轻 -> 0.10
中等 -> 0.20
偏重/重点防控 -> 0.30
三、先验风险计算公式
先做一个简单线性加权就够了：

prior_risk =
0.25 * phenology_risk +
0.25 * humidity_risk +
0.20 * rainfall_risk +
0.15 * temperature_risk +
0.15 * report_risk
最后限制在 0~1：

prior_risk = min(1.0, max(0.0, prior_risk))
四、模型修正层
如果你后面整理出一批弱标签，就加这一层。
如果暂时还没有，就先跳过，只用规则层。

模型输入特征
建议先用这些：

crop
disease
region_code
month
phenology_stage
temp_mean_3d
temp_mean_7d
humidity_mean_3d
humidity_mean_7d
rain_sum_3d
rain_sum_7d
consecutive_rain_days
prior_risk
report_risk_hint
observation_signal
模型选择
优先：

LightGBM
XGBoost
不建议一开始用：

LSTM
Transformer
模型输出
输出一个 ml_risk，范围也是 0~1

五、规则和模型怎么融合
最稳的是按置信度融合。

有模型时
final_risk = 0.6 * prior_risk + 0.4 * ml_risk
如果你的标签质量提高了，可以慢慢改成：

final_risk = 0.4 * prior_risk + 0.6 * ml_risk
没模型时
final_risk = prior_risk
六、风险分数映射成风险等级
建议先固定：

0.00 - 0.30 -> 0 低风险
0.30 - 0.55 -> 1 轻风险
0.55 - 0.75 -> 2 中风险
0.75 - 1.00 -> 3 高风险
这样前端展示很稳定。

七、未来 7 天趋势怎么算
不要做复杂递推，直接逐日算分。

对未来第 i 天：
取该天预报天气
重新计算该天特征
重新跑规则层
如果有模型，再跑模型修正
得到当天 final_risk
最后拼成：

[
  {"date": "2026-04-10", "risk_score": 0.62},
  {"date": "2026-04-11", "risk_score": 0.68},
  {"date": "2026-04-12", "risk_score": 0.73}
]
趋势方向判断
用最后一天和第一天比较即可：

差值 > 0.08 -> 上升
差值 < -0.08 -> 下降
否则 -> 平稳
八、主导因子怎么产出
这个对前端和 LLM 都很有用。

做法很简单：
把各子分数从高到低排序，取前 3 个。

例如：

humidity_risk = 0.30
phenology_risk = 0.30
rainfall_risk = 0.25
输出：

[
  "持续高湿",
  "当前处于拔节期敏感阶段",
  "近7天降雨偏多"
]
九、一个完整例子
以“黄淮海区冬小麦白粉病”为例：

输入
地区：黄淮海区
物候期：拔节期
近 3 天湿度：84%
近 7 天降雨：16mm
温度：18°C
官方报告：中等发生
子分数
phenology_risk = 0.30
humidity_risk = 0.30
rainfall_risk = 0.20
temperature_risk = 0.20
report_risk = 0.20
先验分
prior_risk =
0.25*0.30 + 0.25*0.30 + 0.20*0.20 + 0.15*0.20 + 0.15*0.20
= 0.25
你也可以把子分数设计得更“满”，比如直接按 0~1 打分。
更建议这样：

phenology_risk = 1.0
humidity_risk = 1.0
rainfall_risk = 0.7
temperature_risk = 0.8
report_risk = 0.67
再按权重融合：

prior_risk =
0.25*1.0 + 0.25*1.0 + 0.20*0.7 + 0.15*0.8 + 0.15*0.67
= 0.86
这更适合作趋势图和等级输出。
