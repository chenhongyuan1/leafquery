◆  一、产品概述

▸  1.1 项目背景
我国是世界上最大的农业生产国，粮食安全事关国家根本。水稻、玉米、小麦三大主粮的病虫害每年造成的减产损失保守估计超过数百亿元。农业病虫害的防控历来依赖人工巡田、专家会诊，存在响应慢、人力成本高、信息传递不及时等痛点。与此同时，"精准农业"和"数字农业"已成为国家农业现代化的重要战略方向。
本项目 LeafQuery（"叶问"）正是在这一背景下诞生。通过将 AI 图像识别技术、气象大数据、规则引擎与知识库四者深度融合，构建一套面向普通农户的、轻量化的、移动端优先的智慧农业辅助决策系统。
▸  1.2 产品定位
LeafQuery 是一款主打"病虫害识别 + 气象关联趋势预警"双核功能的农业 AI 移动应用。核心目标是让一个没有专业植保背景的普通农民，也能在 30 秒内完成"拍照识病 → 查趋势 → 获取防控建议"的完整闭环。
目标用户群：华北、东北、长江中下游、华南、西南、西北六大农业生态区的水稻、玉米、小麦种植户及基层农技推广员。
核心价值主张：用 AI 代替专家初诊，用气象大数据代替经验判断，把原本需要"打电话找农技员"才能得到的信息，放在农民手机里。
▸  1.3 六大农业生态区覆盖
系统通过调用和风天气城市搜索 API（GeoAPI），智能将用户所在城市自动归类至六大农业生态区，确保历史气候模型与实际种植环境相匹配：
华北区：北京、天津、河北、山西、山东、河南
东北区：黑龙江、吉林、辽宁、内蒙古
长江中下游区：江苏、上海、浙江、安徽、江西、湖北、湖南
华南区：广东、广西、海南、福建
西南区：四川、重庆、贵州、云南、西藏
西北区：陕西、甘肃、青海、宁夏、新疆
◆  二、核心功能模块（V1 已实现）

▸  2.1 AI 叶片病害识别
用户拍摄或从相册选取疑似染病作物叶片照片，后端调用深度学习视觉模型进行病害识别，数秒内在对话界面返回：病害名称、置信度、图文描述及初步防控建议。
● 功能特点
支持语音输入查询，识别结果以流式对话气泡形式展现，拟人化交互体验。
错误与异常以 Toast 通知形式展示，不中断对话主流程。
每次识别结果自动写入"我的农场"对应作物的历史记录，构建个人病害档案。
历史识别卡片在首页实时同步展示，支持图片回溯查看。
▸  2.2 农场管理（"我的农场"）
用户在"我的农场"页面管理个人农场的种植信息，系统以此为基础提供个性化预测。
● 作物管理（V1 聚焦三大主粮）
可添加：水稻（防范稻瘟病、纹枯病）、玉米（防范大斑病、锈病）、小麦（防范白粉病、条锈病）。
一个农场账号最多添加3种作物，避免信息过载。
● 城市绑定（和风天气 GeoAPI 模糊搜索）
添加作物时，用户输入所在城市名称（支持模糊搜索，如"秦皇岛"→ 返回"秦皇岛 海港"、"秦皇岛 北戴河"等精细到区县的区划列表）。
系统自动将选中城市归入六大农业生态区，作为气象关联预测的地理参数。
城市绑定后，对应的和风天气 LocationID 被持久化存储，后续预测直接使用，无需重复选择。
● 数据持久化
农场数据（作物列表、城市绑定、LocationID、识别历史）通过 localStorage 实现本地持久化，刷新后不丢失。
▸  2.3 气象关联病害趋势预测
这是 LeafQuery V1 的核心竞争力功能，也是区别于普通识别类 App 的最大差异点。系统将实时气象数据与农业病理知识库结合，用定量化的方式输出未来的病害风险评估。
● 数据来源：和风天气 JWT 鉴权 API
使用 Ed25519 非对称算法在后端生成 JWT Token，所有私钥均在服务端处理，前端零接触，安全合规。
调用三个接口：逐日 7 天天气预报（/v7/weather/7d）、逐小时 24 小时预报（/v7/weather/24h）、历史天气时光机（/v7/historical/weather）。
所有 API 返回数据均为 gzip 压缩格式，后端使用 java.net.http.HttpClient + GZIPInputStream 进行解压处理，确保数据正确解析。
接入内存缓存（ConcurrentHashMap TTL 机制），预报类数据缓存 3 小时，历史数据缓存 24 小时，有效降低 API 调用频率。
● 气象特征提取（WeatherFeatureService）
tempMean3d：近 3 天逐小时平均气温（真实数据）
humidityMean3d：近 3 天逐小时平均相对湿度
rainSum7d：近 7 天累积降水量
consecutiveRainDays：连续降雨天数（0-7天）
未来 7 天逐日气温与降水预报（用于趋势推演）
● 五因子加权规则引擎（RuleBasedRiskEngine）
核心预测逻辑通过以下 5 个维度加权计算，最终得出 0-1 之间的标准化风险评分（Prior Risk Score）：

● 风险等级与趋势判定
低风险（≤30%）：绿色展示，气象条件不利于病害发展。
中风险（31%-55%）：黄色展示，建议关注；气象接近发病临界点。
高风险（56%-75%）：橙色展示，建议提前预防性用药。
极高风险（>75%）：红色展示，建议立即采取防控措施并联系农技员。
7天趋势方向：通过比较后3天与前4天的平均风险评分，判断为"上升"、"下降"或"平稳"，辅助决策。
● 主驱动因子解读（topDrivers）
系统自动提取本次预测中得分最高的 3 个因子，以人类可读的自然语言说明呈现（如"当前处于抽穗期敏感阶段"、"近7天累积降雨偏多(47.3mm)"），帮助农民理解风险来源，而非仅看数字。
● 病害选择与物候期选择
用户可在预测页选择当前作物正在防范的具体病害（如"稻瘟病""纹枯病"），获取该病害专属的分值权重。
用户还可选择当前所处物候期（苗期/分蘖期/拔节期/抽穗期/灌浆期等），系统自动调用对应的敏感度配置。
▸  2.4 发现与知识库
"发现"页为农民提供三类内容服务：农业资讯（News）、植保知识库文章（Knowledge）和社区问答（Q&A），内容数据存储于 MySQL 数据库，通过 Spring Boot MyBatis 接口统一提供。前端通过 Tab 切换动态加载，避免初始化时的全量请求。
▸  2.5 首页识别历史同步
首页展示用户最近的识别历史记录，包括识别出的病害名称、置信度、作物类型及识别图片缩略图。图片路径从数据库字段获取，与实际存储路径精确匹配，确保图片正常回显。
◆  三、系统技术架构

▸  3.1 总体架构（三层）
展现层：Vue 3 + Pinia + Vue Router 移动端 SPA，Vite 开发/构建，TailwindCSS 原子化样式，适配手机 375-430px 视口。
业务逻辑层：Spring Boot 3（Java 17），提供 RESTful API，含 AI对话、农场管理、气象预测、城市搜索。
模型/数据层：Python Flask 微服务（端口5000）负责 AI 图像推理；MySQL 8 存储用户、作物、Discovery 内容数据；和风天气 API 提供实时与历史气象数据。
▸  3.2 关键技术选型说明
和风天气 JWT 鉴权：采用 Ed25519（EdDSA）算法，私钥在后端的 application.properties 中安全存储，JWT 有效期 15 分钟，每次请求在服务端临时生成，不向前端暴露任何密钥。
Gzip 自动解压：和风天气所有接口均返回 gzip 压缩数据，后端通过检测响应头 Content-Encoding 与响应体魔数（0x1f, 0x8b），对压缩数据进行透明解压。
Vite 代理配置：前端开发模式下，所有 /api 请求被代理到 localhost:8080，生产部署时可通过 Nginx 实现同域转发，避免跨域问题。
前端状态管理：useFarmStore（Pinia）统一管理农场数据，localStorage 实现免登录持久化，App.vue 初始化时自动 init()。

◆  四、近期迭代计划（V2 —— 机器学习增强版）

V2 版本的核心目标是将"规则驱动"升级为"数据驱动"，引入机器学习模型，使预测结果更精准、更具解释性，并支持物候期自动推算，实现真正意义上的"傻瓜式"智能预警。
▸  4.1 物候期自动推算（积温模型）
若获取到玉米/水稻/小麦的历史物候变化数据集（包含各区域、各年份的播种-成熟日期及对应积温），可以实现：
基于 GDD（生长度日 = Σmax(0, 日均温 - 基础温度)）累积算法，结合播种日期与当地历史气温，自动计算出农田目前大概率处于哪个物候期。
前端用户无需手动选择物候期，系统开屏直接提示："根据当地积温数据，您的水稻预计已进入抽穗期（高风险敏感窗口）。"
可结合未来 7 天气温预报，预测下一个物候期的到来时间，提前发出阶段性预警推送。
📌  如果产品团队可提供玉米/水稻物候变化数据集（CSV 格式），可直接接入到 WeatherFeatureService，计算工作量约 2-3 天。
▸  4.2 LightGBM / XGBoost 病害预测模型
在 Python Flask 微服务中训练并部署机器学习模型，以替代或并行于当前纯规则引擎。
特征矩阵：tempMean3d、humidityMean3d、rainSum7d、consecutiveRainDays、phenologyStage（编码）、region（六大区编码）等。
标签：历史病害发病记录（0=未发病, 1=轻度, 2=中度, 3=重度）。
接入方式：TrendForecastService 新增 /python-service/ml-predict 调用，将气象特征传入 Python 服务，返回 ML 预测分作为第六种因子叠加进规则引擎结果，modelVersion 字段升级为 "hybrid_v2"。
模型解释：SHAP 值支持，以 topDrivers 格式在前端展示 ML 模型的特征重要性排序，增强可解释性。
▸  4.3 可视化大屏（区域病情地图）
基于六大生态区用户数量与上报数据，生成区域病情热度地图，供农技推广部门参考。技术方案：ECharts GeoMap + Spring Boot 数据聚合接口。
◆  五、中远期规划（V3 —— 大语言模型深度融合）

V3 版本将引入 LLM（大语言模型）作为智能"农业顾问大脑"，实现从"给数据"到"给决策"的最终跨越。
▸  5.1 LLM 生成个性化防控方案
当前 AI 识别仅返回通用病害描述。V3 将在识别结果出来后，自动将"作物品种 + 当前物候期 + 当地气象条件 + 病害类型 + 严重程度"组装成结构化 Prompt，调用 Doubao Lite/Pro API 生成 200-400 字的个性化防控方案，包含：推荐农药品种与用量、施药时间窗口、注意事项、下次复查时间。
▸  5.2 RAG 知识问答（植保大模型）
以现有 Discovery 知识库文章作为文档语料，通过向量化检索（Embedding + VectorDB）实现检索增强生成（RAG），让用户在对话界面直接问"水稻稻瘟病用什么农药最好""最近天气适合打药吗"，AI 返回基于本地权威知识库的精准答复。
▸  5.3 多模态病虫害百科图鉴
构建由 LLM 辅助生成的病虫害知识图谱，支持"以病索药""以药索病"双向检索，为农技推广员提供专业数字化工具。
▸  5.4 微信小程序 / Flutter 跨端
将现有 Vue 移动端 WebApp 发布为微信小程序或 Flutter App，接入微信生态（消息推送、地理位置），进一步降低使用门槛，覆盖更广泛的农村用户群体。
◆  六、竞赛评审亮点总结

【技术深度】全链路真实数据接入：拒绝 Mock，从 AI 模型推理到气象 API 均为真实调用，和风天气 JWT Ed25519 鉴权实现符合官方最高安全标准。
【产品完整度】已打通从"用户添加城市 → 气象数据获取 → 规则引擎评分 → 前端可视化"的完整数据流，五因子加权规则引擎+7天风险趋势图+主驱动因子解读均已落地。
【农业场景针对性】六大农业生态区自动归类、三大主粮病害专项规则配置（含物候期敏感度矩阵），展现了对农业领域的深入调研与思考。

【用户体验】移动优先的 UI 设计（下拉弹出层、Toast 通知、glassmorphism 渐变等），城市模糊搜索精准到区县级别，极大降低了农村用户的使用门槛。

◆ 最新迭代核心架构特性 (v1.5 Feature Snapshot)
在最近的版本迭代中，系统在云端数据流及界面包容性上取得了长足进步，具体架构升维如下：
【“我的收藏”全端云同步体系】
架构设计上新增了 user_favorite 数据库核心表，采取“冗余快照字典”模式设计，避免复杂连表耗时。结合 Vue 3 Pinia 的响应式数据栈管理，应用启动时 (App.vue生命周期) 自动下发 Axios 同步云端数据，实现多端（跨手机浏览器与PC）对于资讯、图鉴的秒级心跳同步。并独立设计出了全局毛玻璃高颜值沉浸式“我的收藏”展陈卡片。
【识别记录深层持久化与无缝容错渲染】
告别单一的浏览器 LocalStorage 本地存储，AI 预测的诊断结果（包括无限制的 Base64 原始分析影像：LONGTEXT引擎）被永久存入数据库，与用户主键强绑定关联。在列表及横向轮播渲染机制上（如 Records.vue 与 Identification.vue），自研了前置异常阻断策略 (@error平滑回退处理)，哪怕旧版本的失效脏图片链接，系统亦会自动无缝降级映射为绿色有机 Emoji (🌿/🦠/🐛)，拒绝传统“碎图”报错，保障极致统一的高级产品视觉观感。
【发现页业务层全栈重构】
将前期的静态交互稿全部对接至 Spring Boot 底层表结构。涵盖“农技资讯 (News)”、“植物图鉴百宝箱 (Knowledge)”以及“专家问答社区 (QnA)”等模块的持久层打通和统一主键规范。
【多模态方言大模型交互流】
用户可直接在预测主页或发现页通过按压极具科技感的呼吸光圈麦克风，录制方言音频（支持流式音频 PCM 到 WAV 在前端浏览器的平滑降采样转化），交由后端 Python 微服务识别解码后直通大语言模型（LLM）实现无延迟语义提取与防范建议生成，极大贴合真实三农作业的使用环境。

◆ 智能语音识别与交互体验升级（新增特性）
为了提升农户在田间地头实地操作时的便捷性，LeafQuery 系统在原有的图像识别、文本交互基础上，深度结合了前沿的 Web Audio API 与 HTML5 Canvas 技术，首创了农技问答场景下的沉浸式（Immersive）语音交互体验。本次更新主要包含以下核心功能亮点：
1. Organic AI Orb：仿生流体视觉反馈
在用户开启语音录入时，传统的生硬按键被替换为全屏级“有机流体球（Organic AI Orb）”。系统在背后利用了基于高分贝检测和均方根（RMS）音频能量分析算法。通过精确复刻 7 个控制点的贝塞尔曲线（Bezier Curve）与正余弦波形叠加，流体球在接收到用户发声时会随音量强度产生真实、有规律的外扩震动与形态变化。
• 视觉渲染： 采用纯原生 Canvas 绘制配合多重径向渐变，形成契合系统植保主题的“绿-青”动态融合表现。加上动态高斯模糊 Glow 辉光和混合叠加的 Film Grain（胶片噪点），提供具有生机感（Organic）的高级视觉质感，且在所有主流浏览器中均保持 60fps 的稳定帧率交互。
2. 无缝融合的长按录音与多方言支持
• 交互方式： 用户只需“长按”屏幕下方的超大号麦克风悬浮按钮，即可唤出沉浸式 AI 倾听覆盖层（Overlay）；“松开”手指即刻完成录音提交，极大地简化了复杂环境中的操作流程，防止用户误触。
• 语音流处理： 考虑到农民群体的使用习惯，系统深度接入了多方言支持功能（含粤语、上海话、闽南语、四川话、陕西话等）。前端直接利用 ScriptProcessor 捕获音频 PCM 流并进行重采样，转码为 16kHz 标准 WAV 格式后，经由云端火山引擎大模型实时解析。
3. 全局 Toast 弱侵入式异常消息提示
鉴于实际使用场景中可能存在的麦克风权限阻止、弱网状态或语音未识别出有效内容，传统的 Alert 弹窗或错误对话内容极其破坏交互连贯性。本次重构彻底引入了一套顶部滑出的弱侵入式 Toast 通知系统：
• 智能嗅探： 自动拦截后端抛出的无效配置（如 API 密钥挂载失败）、超时、分析异常或“未识别出有效内容”提示，避免无效指令混入问答对话框。
• 视觉分级： 提供 info、warning（琥珀色）、error（红色）多级颜色匹配与自动消失机制，确保异常反馈既被用户感知，又不阻塞核心流程。
4. 历史记录一体化与全平台数据互通
为了帮助农户回顾溯源此前的病虫害记录，我们：
• 本地与云端双向同步： 最新扫描的病虫害置信度、图片、病情名称及分析会同时存入本地 localStorage 和云端 Database，首页“最近记录”横列可随手翻阅历史卡片。
• 功能直达互通： 首页点击“全部”按钮即可实现 Vue Router 的跨页面平滑跳转，连接至新建的“识别记录”总览页面，方便后续导出甚至咨询专家。

◆ 发现页重构与全链路动态生态数据中心
为了打造更具互动性与实用价值的农业聚合社区，本次更新对“发现页（Discovery）”进行了彻底的底层重构与全链路 API 驱动改造。彻底淘汰了早期的静态 Mock 数据，依托 Spring Boot 强健的后备支持与优雅的 MyBatis 数据库架构，带来了以下核心业务模块的全面进化：
1. 动态植物库与专属病虫害图鉴 (Knowledge Base)
系统现已内建了丰富的农业核心农作物（如番茄、黄瓜、水稻、玉米等）的结构化植物表。
• 智能两级分类展示： 用户点击植物标签即可下钻进入该作物的专属病虫害图鉴页面。图鉴数据依据病理状态被精准分类为“真菌病害”、“病毒”、“细菌”、“缺素/生理障碍”以及“健康状态”。
• 沉浸式详情弹窗： 引入优雅的模态框（Modal）交互，大图覆盖配合高斯模糊背景展示病虫害高清特写，提供结构化的“症状特征”描述与数组解析化的详细“防治方法与用药建议”。
2. 农业资讯与前沿动态推送 (News & Recommendation)
发现页“推荐”标签现已实时接入农业资讯系统：
• 数据全貌： 自动追踪展现《夏季西红柿常见病害防治指南》、《农业补贴新政策解读》等实时推文，带有定制化的彩色角标（如“热门技术”、“政策解读”）。
• 阅读体验： 后端统计阅读量与发稿时间流，前端运用 Vue 的平滑过渡呈现结构清晰、行距舒适的非阻断式聚合阅读面板。
3. 专家图文问答圈 (Q&A Community)
打造了贴近农户诉求的互助求教板块，解决疑难杂症：
• 黄金标准的富媒体存储： 基于业界最佳实践，数据库层面利用 JSON 数组结构优化存储至多 3 张高清报事图片。在避免繁重多表 Join 的同时，实现了最优雅的数据流通。
• 卡片式互动组件体验： 问答信息流（Feed）卡片内聚了“农户诉求详情”、“多宫格预览图”，特有的“专家解答专属高亮回帖区”（绿色底纹警示），此外全面支持用户对帖子进行点赞（点亮星号）和展开实时交互式评论盖楼。
4. 全局五角星收藏体系 (Global Favorites System)
重组了视觉与心智模型，系统层面融入了跨模块全局收藏：
• 极致一致的视觉标记： 废弃了混杂的心形图标，全局统一采用标准化的、辨识度极高的星形（⭐ 态为已收藏/☆ 态为未收藏）来传达收藏与点赞倾向，匹配金黄色（Amber）的视觉强调。
• 一键收录： 利用 Pinia 的 Store 响应式模型，当用户在阅读资讯或图鉴时，只需一键点击浮动星号即可将宝贵资料归档入个人的农技资源库。

◆ 前端视觉与物理动效全面升级（PC 端高级特性）
在打造沉浸式的现代 Web 体验方面，LeafQuery 针对 PC 平台进行了系统级视觉重构。我们抛弃了传统的平面布局，全面引入了基于原生 CSS 3D 转换与 HTML5 Canvas 的物理级特效，旨在打造极具未来科技感与高级质感的用户连接点。本次主要更新包括以下核心方向：
1. 沉浸式 3D 柱状曲面卡片轮播 (Inside Cylinder Carousel)
针对农业核心技术与功能的展示模块 "VISION"，团队首创了第一人称视角的 3D 内圆柱面滚轮（Inside Cylinder Track）。
• 空间透视算法： 利用动态计算的 Y 轴旋转角结合 `140vw` 的平缓曲率半径（Radius）以及高达 `2000px` 的视距（Perspective），构建出包围用户的全景式大屏卡片组。
• 滚动融合驱动： 所有卡片的入场、退场、位移及透明度，均深度绑定用户滚动进度（Scroll Progress）。搭配 `+/- 60vh` 的大跨度错落排版（Stagger），实现了"推拉镜头"般的极致纵深沉浸感，有效聚合了海量图文信息。
2. 基于 Canvas 的动力学粒子与网格畸变引擎
在网页底部的产品下载（CTA）区域，为了强化高频转化场景的交互质感，我们用高度定制的物理变形动效取代了传统的“死白”二维码展示框。
• 流变式“GO”感应区： 下载触点被设计为一个发光的“GO”呼吸圆盘。当用户鼠标悬停时，圆圈将顺滑展开并呈现出其内部暗藏的微观粒子二维码。
• 引力互斥与空间畸变 (Repel & Squeeze)： 底层部署了基于 60fps 重新计算的微型 2D 物理引擎。网格系统的每个相交点都会实时监听“GO”圆盘的状态，并在用户悬停时被强大“排斥力”迅速挤压排开。
3. 极致调教的非线性运动美学
在这套物理背景网格系统的动效表现上，团队经过反复打磨，引入了极端的加速模拟，彻底消除“线性动画”的干瘪感：
• 十二次幂 (Power 12) 加速曲线： 为了营造出强烈的“张力爆发”感，我们在底层数学运算中应用了高次幂算法。在整个 1000ms 的动画生命周期中，前 80% 的时间被“克制”在近乎静止的蓄力状态，而在结尾几十毫秒内所有元素如火山般瞬间弹开。
• Global Zoom 全局缩放： 网格被挤压推开的同时，底层画布会同步跟进 1.15 倍的等比放大。配合 `cubic-bezier(0.95, 0, 0.05, 1)` 带来的视觉冲击，使得简单的绿色坐标系网格爆发出宏大、富有空间扭曲感的高级科技质感，并完美契合上方 VISION 区的亮绿色彩基调。
